# 30日間の大会・自動バランス検証（2026-09-14）

## 結論

既定ルールで、購入・栽培・販売・出品予約・10/20/30日目の提出・終了までつながる経路を確認した。丁寧な管理では両作物ともS評価に到達する。今回の操作経路では資金不足による停止なし。

一方、栽培に比べて大会待ちが長く、用水路の常時給水は水分過多になりやすい。これらは調整候補であり、今回は価格・成長速度・給水量・評価基準を変更していない。

これは実際のSystemを使う自動テストであり、Release画面を人が30日間操作したプレイ動画や、初見の遊びやすさの実証ではない。週間報告の動画成果としては加点しない。

## 再現方法

プロジェクトルートで実行する。

```powershell
cmd /c tools\tests\run_farm_season_balance_test.cmd
```

Visual Studio 2026 Communityの既存テスト環境を使用する。`generated/codex_checks`に専用EXEと中間ファイルを生成し、標準出力にCSV形式の各結果と合否を出す。ゲームEXEや実セーブは使用・変更しない。失敗時は理由と終了コード1を返す。

## 検証条件

- `FarmRules`既定値、5×4マス、初期300G、種0個、Day1から開始。1日60秒。
- 1/60秒の固定ステップ。成長・水分・日付は実装済みSystemを呼ぶ。日付スキップや、成長・品質・所持金の直接代入はしない。
- 各期間の初日に同じ1マスで2個を順に育てる。1個目を保護・予約し、2個目だけを売却する。これを3期間繰り返し、計6個購入・6個収穫・3個販売。
- 手動管理：植付け前に堆肥。カブH0、ニンジンH1。じょうろで開始水分をそれぞれ0.50/0.60以上にし、育成中0.35/0.45未満で0.10ずつ給水。
- 乾燥放置：H0、堆肥なし、水やりなし。手動管理とは水分以外にも土・地形条件が違うため、水分だけの効果を分離する実験ではない。
- 常時給水：堆肥あり、畑に隣接した用水路とその隣の水源を維持。カブは全てH0、ニンジンは全てH1。じょうろは使わない。毎ステップ接続と有限水量の保存誤差を確認する。
- 各操作は時間停止中相当で実行する。人の判断・入力・移動時間や収穫アニメーションの待ち時間は含めない。
- 2作物×3管理方法×3速度（1/2/4倍）×2終了方法＝36ケース。
- 終了方法は、3大会すべて提出してDay30で終了、または最終回を見送ってDay31で期限終了。

## 分かった課題と次の順序

1. **給水の調整手段が必要。** この常時接続例では成長時間の大半が水分過多だった。自動給水そのものを高得点保証にせず、流量・開閉を操作し、水分予測をHUD/ImGuiで見られる形を次に検討する。設定はまだ変更しない。
2. **大会待ちの長さを検証する。** 1個10～15秒で育つ管理経路に対し、大会間隔は600秒。6個だけを作る最短操作経路では待ちが多い。人のプレイで追加の栽培や土地作りが自然に埋めるか確認してから、日数・成長時間・安全な時間送りを調整する。
3. **S評価は到達可能だが難易度は未確定。** 入力を自動化した最適寄りの管理が300/297点になることは確認済み。初見プレイヤーが無理なく操作できるかは別問題。全行動経路で資金詰まりがないとは保証しない。
4. **水路の高さを明示する。** ニンジンの畑H1に対してH0の水路では給水されない。初回の検証配置でこの条件に気づき、水源・水路もH1へ修正した。低い水路から高い土へ水が上がらない現在のルールは維持する。

## 検証範囲

資金の差引、保護品の売却除外、実際の収穫日・サイズ記録、予約・提出、古い世代の拒否、重複提出拒否、案内待ちと終了時の進行停止、30/31日の境界、全3速度、有限水量の保存誤差を確認した。

UI経由の操作、Save/Loadを挟んだ全期間プレイ、Undo/Redoとの全組合せ、大規模な水路配置、GPU性能、初見プレイヤーの所要時間は今回の対象外。Sceneの呼出し順をテスト側で再現しているため、Sceneの配線や入力を含むRelease実機検証は別途必要。
