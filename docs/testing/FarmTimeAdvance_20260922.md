# 安全停止付き早送りの内部基盤（2026-09-22）

## 実装済みと未接続の境界

`FarmTimeAdvanceSystem.h` に、開始・中止・停止理由・対象マス・目標日・実行刻み数を持つセッション専用Systemを追加した。Visual Studioプロジェクトにも登録済み。

**SceneおよびUIにはまだ接続していない。現在のプレイ画面から新しい早送りは使えない。** ユーザーが希望するUI/HUD案を先に確認してから操作導線を作る。既存1/2/4倍ボタンの動作や配置は変更していない。

## 処理と責務

1. `Start` で全植付けマスの状態と時計を確認する。既に水不足・乾燥・水過多・収穫可能なら開始しない。
2. 次の未提出の大会日を目標にする。大会モードで未来の対象がなければ31日目を終了境界とする。体験版で目標がなければ開始しない。
3. `AdvanceBatch` は最大64刻み。1刻みは倍率適用前1/60秒以下で、残りの目標日までの時間より大きくしない。給水→成長→大会時計→終了判定の順に既存Systemを呼ぶ。日付の直接代入はしない。
4. 各刻みの前後で状態を確認する。大会案内、終了、収穫可能、水不足/乾燥、水過多で停止。大会・終了を優先し、作物由来の理由はマス番号順の最初の対象を返す。
5. 明示キャンセルと、呼出し元の禁止状態（メニュー、観察比較、プレビュー、フォーカス喪失など）で停止する。Gridの世代/同一性や時計/倍率が変わった場合も再開せず停止する。

停止しても過去の成長や給水は巻き戻さない。水分異常の境界を跨いだ最初の小刻みで止まるので、過多や不足を完全に防ぐ機能ではない。全畑を監視し、選択マスだけを見る機能ではない。

Systemは呼出し時だけ既存Systemの参照を借用する。保存するGrid/Dateのポインターは同一性比較だけに使い、後から参照先を読み出さない。ロード・リスタート・Systemの入替え時には呼出し元が必ずResetする。早送り状態はセーブしない。

## 検証

```powershell
cmd /c tools\tests\run_farm_time_advance_test.cmd
cmd /c tools\tests\run_farm_season_balance_test.cmd
```

- 専用テスト: `/O2 /DNDEBUG /W4 /WX` でコンパイル・実行成功。assertに依存せず失敗時に終了コード1を返す。
- 1/2/4倍、カブ/ニンジン、選択していないマスでの収穫可能・低水分・水過多の検出。
- 境界直前から最初の1刻みで収穫/低水分/水過多となり、その後の刻みを実行しないこと。
- Day9/19/29の59.99秒から10/20/30日目で停止。時計だけでなく給水側の刻みも残り時間以下であること。
- 大会案内待ちでは開始拒否、30日目確認後は31日目で終了。体験版Day31は対象なし。
- 64刻みの上限、通常Systemを同じ回数呼んだ場合との時計・水分・成長・観測時間の一致。
- 二重開始拒否、中止後の非進行、禁止状態、Grid復元/別Gridへの差替え、日付/倍率の外部変更後の停止。
- NaN/Infinity/範囲外の水分・成長、未対応作物の拒否。壊れたメモリーを模擬するケースだけ、検証用Gridの値を直接変更している。実セーブは使わない。
- 空の畑から自然進行でDay10まで到達し、上限内で停止。
- 既存72ケースの30日間テストも成功。こちらは新早送りを使わない既存Systemの回帰検証。
- Debug / Release x64のビルド成功。今回のヘッダーはまだSceneから参照されないため、新機能のコンパイル・動作実証は専用テストが担う。

初回はNaNを通常のSetTile経由で設定しようとしたため、テスト用データ作成自体が拒否された。意図した不正メモリーテストのみGetMutableTileを使う形へ修正し、最終テストが成功した。製品側の入力検証は緩めていない。

## 性能と残課題

新System自身に動的確保や所有リソースはない。1呼出し64刻みとセッション120000刻みの上限を持つ。全畑走査と既存のIrrigation更新を繰り返すため、実機でのCPU時間を測ってから1フレームあたりの実行数を決める。64刻みを64倍速と表示してはならない。セッション上限の強制到達経路は未検証。

DX12、Descriptor、Barrier、Fence、VRAM、DrawCall、描画処理は変更していない。ゲームの起動・GPU性能検証・週次報告動画は未実施。

次段階では、通常FixedUpdateとの二重更新防止、未保存管理、Timelineの扱い、画面/編集/比較/フォーカス切替時のキャンセル、ロード/再開始時のReset、停止対象マスへの誘導を接続する。比較中は比較Systemを更新せず、早送り自体を禁止する。接続前にUI/HUD案を確認する。
