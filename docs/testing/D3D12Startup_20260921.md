# DirectX12起動修正と実機確認（2026-09-21）

## 修正範囲

以前の起動停止は、Device作成のHRESULTを確認せず、null DeviceでCommandAllocator作成へ進んだことによるアクセス違反だった。今回はその経路を修正した。今日のRTX環境では旧クラッシュ自体は再現しておらず、以前のCDB記録と現行コードを根拠にしている。

- `D3D12DeviceSelection.h` が高性能順のhardware adapterを列挙し、各GPUでFL12_2 → 12_1 → 12_0を試す。作成後に現在のshaderが要求するShader Model 6.0を確認する。
- Software adapterは選ばず、WARPへ黙って切り替えない。失敗した候補のDeviceはComPtrで解放する。列挙エラーと列挙終端を区別する。
- `DirectXCommon` はFactory、Device、CommandAllocator、CommandList、CommandQueueの失敗を検出し、処理名とHRESULTを記録する。成功時はGPU名とFeature Levelを記録する。
- `Framework` はこの起動例外で、未初期化の後続SystemのFinalizeを呼ばずに初期化済み範囲を片付ける。`main` はエラーを表示して失敗終了する。Game/Sceneに描画資源選択の責務は加えていない。
- 通常フレームの処理、DrawCall、Descriptor、Barrier/Fence、セーブ形式は変更していない。探索と候補Device作成は起動時だけ。

## 検証結果

`tools/tests/run_d3d12_device_selection_test.cmd` は `/std:c++20 /W4 /WX` で合格。

| 対象 | 確認結果 |
|---|---|
| null Factory / Adapter | E_POINTER、Deviceなし |
| NVIDIA GeForce RTX 4060 Laptop GPU | FL12_2でDevice作成成功 |
| Intel UHD Graphics | FL12_2は0x887A0004、FL12_1でDevice作成成功 |
| Microsoft Basic Render Driver | Softwareとして選択しない |
| 高性能順の選択 | RTX、SM6.0対応、CommandAllocator作成成功 |
| Debug x64 / Release x64 | 両構成のビルド成功 |
| Release実画面 | コピーした農場データから起動・操作成功（RTX） |

IntelはDevice作成までの検証であり、Intelでのゲーム全体描画は確認していない。全GPU非対応時のMessageBoxと終了経路は実機の障害注入では未検証。SwapChainなど残りの初期化処理全般の失敗処理を修正したわけではない。GPU負荷・VRAMの実測はしていない。

## 給水UIの追加確認

元のセーブや提出動画を使って上書きせず、`generated/codex_checks/intake_runtime_20260919` のコピーで実操作した。

1. 畑7の給水を切ると土の水分100%は保持され、水路の水も残った。
2. 種を植え、成長中に水分99% → 73%、成長2% → 96%を確認した。作物のない土が時間だけで乾くという意味ではない。
3. 給水を入に変更し、Undoで切、Redoで入に戻った。変更中は時間停止、水分72%を保持した。
4. 農場へ戻ると水分72% → 81%へ増加した。
5. 1280×720と1920×1080で入／切UIと停止中HUDを目視した。確認した画面で文字の重なり・見切れなし。

給水専用テストとRuntime Viewテストも再実行して合格。同日の後続検証で、Releaseから日本語名で保存して再起動し、給水停止の復元を確認した。Debug Inspectorの切替・Undo/Redo・上書き保存も実操作で確認済み。詳細は [給水の検証記録](FarmIrrigationIntake_20260919.md) を参照。全操作の動画収録は行わず、週次報告の採点は変更していない。
