# 正式3作物の30日間バランス検証

## 結論と範囲

正式作物のニンジン・トマト・かぼちゃと、旧セーブ互換のカブについて、実際のSystemを通した144ケースを検証する。従来の72ケースは旧2作物だけだったため、正式作物への移行後の保証としては不足していた。

全ケースで購入6回、収穫6回、保護品を除く販売3回、大会への提出、終了まで成立した。手動で適正水分を維持する経路では正式3作物ともゲーム内大会のS評価に到達した。今回の変更はテストと文書のみ。ゲームの価格・成長速度・保存形式・大会の採点規則V1は変更していない。

これは自動検証であり、人による30日間の操作・Release画面確認・週間報告用の動画ではない。大会の点数は300点満点で、学校の週間報告点とは無関係。

## 再現

```powershell
cmd /c tools\tests\run_farm_season_balance_test.cmd
```

`tools/tests/farm_season_balance_test.cpp`を`/O2 /W4 /WX`でコンパイルし実行。測定ログは`generated/codex_checks/formal_season_balance_final.log`。標準出力はCSVヘッダー・測定行・PASS、標準エラーは実行条件と失敗理由。`RUN:`の直後に失敗した場合は、その作物・管理・倍率・終了経路を確認する。

- 4作物 × 6管理方式 × 1/2/4倍速 × 全3大会提出/最終大会見送り = 144ケース。
- 5×4、Day1、300G、種0個。1マスで各期間2個ずつ順に育て、1個を保護して大会用に予約し、もう1個を売る。
- 水路経路は水源0→水路1→畑2。乾燥経路以外はFarmRulesの適正高さを使い、毎植付け前に堆肥を投入する。乾燥経路はH0・堆肥なしなので、水分だけを分離した実験ではない。
- 手動管理は適正水分帯の中央まで植付け前に給水し、下から25%の位置を下回ったらじょうろで10ポイント足す。全作物共通の方針で、トマトの狭い帯にも一回分の給水が収まることを検査する。
- 水路開閉は0.5/1/2秒おきに判断し、適正帯の下から25%以下で開き、75%以上で閉じる。じょうろは使わない。判断間隔は倍率適用前のシミュレーション時間で、4倍速ではゲーム内で4倍の間隔になる。
- 人の反応、クリック、植付け、取引、堆肥投入の所要時間は含めない。水分・生育・品質・所持金・日付を直接書き換えず、プレイヤーの操作APIとSystem更新を使う。

手動管理の基準を作物別の固定値から共通の水分帯比率へ変更したため、過去の手動管理の操作数と単純に差分比較しない。開閉方針は従来どおり。

## 判断と残る課題

1. **最終資金だけで強さを決めない。** かぼちゃは高収益だが成長が遅く、初回2個分の種を買うと残金20G。自由購入や同時栽培では結果が異なる。現時点で「かぼちゃ一択」と断定して値下げはしない。
2. **過湿の罰則が重い。** トマト・かぼちゃの常時給水経路は、適正管理より大幅に遅い。今回の毎期間2個は大会に間に合ったが、操作の遅れ・別の配置・追加栽培では保証しない。次の実機確認では水分過多の表示から給水停止へ迷わず移れるかを優先する。
3. **大会サイズ点が途中で頭打ちになる。** V1は0.5～2.0倍を0～40点へ換算する。かぼちゃは平均2.51倍でも出品3個のサイズ点は各40点で、2倍を超えた差が評価されない。これは測定で判明した設計課題であり、今回修正済みではない。作物別のサイズ基準等を導入する際は、保存済みV1結果を再採点せずルールの版管理を設計する。
4. **長い待機はこのテストだけでは判断できない。** 全提出の時計進行は1倍1740.05秒、4倍435.05秒相当。1マス・6個という限定経路で、既存の時間送り機能を呼んでいない。人のプレイ時間や現在の時間送り体験を表す値ではない。

## 安全性と未検証

資金収支・最低資金・品質/サイズの得点合計・有限値・水量保存・閉じた取水口の給水ゼロを確認する。古い在庫世代の提出と二重提出を拒否し、保護品の売却除外、大会案内中/終了後の時計停止を維持。固定tick上限で無限待ちを検出する。手動/乾燥/常時給水は倍率間の得点差3以内・資金差6G以内・評価一致を検査し、乾燥と常時給水が適正管理より高得点/短時間にならないことも確認する。

開閉経路は判断間隔に倍率の影響があるため、倍率間の同得点は要求しない。null、配列範囲、収穫記録の寿命と有限サイズを検査し、System更新をまたいで一時的な参照を保持しない。測定用の固定配列・カウンターだけを追加した。ゲーム本体の新規動的確保、DrawCall、Descriptor、Barrier、Fence、VRAM所有権の変更はない。

今回はテスト実行用プログラムだけをビルドした。Debug/ReleaseゲームEXEの再ビルド・起動、実機操作、混合作物/複数マス、途中保存/ロード、人による難度評価、GPU性能は今回未検証。作物解放日、2×2巨大かぼちゃ、トマトの繰り返し収穫は実装していない。
